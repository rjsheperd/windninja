* Conventions
- *Tests*:
  - Unit tests are Boost.Test cases in =autotest/= and are added to =test_main=.
  - Each case is registered with =add_test(<suite>_<case> ... --run_test=<suite>/<case>)=,
    matching the existing =autotest/CMakeLists.txt= style.
  - CLI integration tests are =.cfg= files under =autotest/config/pass/=.
- *Golden comparison*: compare to the OpenFOAM-11 reference outputs from
  Phase 0. The metrics are:
  - speed: RMSE and max abs diff, in m/s;
  - direction: circular mean abs diff, in degrees;
  - k: relative RMSE.
- *Tolerances*: placeholder values are marked =TBD=. They need sign-off from
  the WindNinja science team before Phase 2 ends.
- *Gates*: =GATE= headings are go/no-go decisions. Don't start the next phase
  until the gate is recorded as DONE or CANCELLED, with a note.

** DONE 2.2 Laminar incompressible solver (pseudo-compressibility) [9/9]
Method (CPU reference, simplest robust choices):
- Artificial compressibility: ∂p/∂τ + β∇·u = 0, ∂u/∂τ + ∇·(uu) + ∇p = ν∇²u
  (p kinematic).
- Convection and pressure: Rusanov flux on the AC system, wave speed
  |U| + sqrt(U² + β|S|²), with linear reconstruction from Green-Gauss cell
  gradients. The face jump is O(h²), so the dissipation is second order and
  plays the Rhie-Chow role against checkerboarding.
- Viscous: face gradient = average of cell gradients + correction along the
  centroid line.
- Pseudo-time: explicit Euler with local Δτ from CFL and a viscous bound.
- BCs: weak, through boundary face states, per block side.
- MMS sources: numerical 4th-order derivatives of the exact solution.
- [X] =src/ninja/rans_solver.{h,cpp}=: state, per-side BCs (no-slip / moving
      wall, slip, velocity inlet, pressure outlet, Dirichlet), source hook,
      residual and local-time-step iteration.
- [X] MMS harness: numerical source terms from an exact solution.
      Result (curved + stretched grid, 8/16/32): converged to a 1e-9 residual
      drop in 500–1000 iterations; 16→32 orders u 2.08, w 2.55, p 1.85.
      Lessons: (1) an all-Dirichlet boundary needs the Rusanov flux between
      interior and prescribed states. Imposing F(state) fixes the boundary
      mass flux, whose O(h²) mismatch with the source made p drift forever.
      (2) A refinement study must hold the *total* stretching fixed (per-layer
      growth G^(1/(n−1))); a fixed per-layer ratio isn't a refinement sequence
      and collapsed the observed order to ~0.1.
- [X] Lid-driven cavity setup (x–z plane, one cell in y with slip sides).
      Ghia Re = 100 values match two independent transcriptions
      (gist.github.com/ivan-pi, github.com/sujaldave/2DLidDrivenCavityBenchmark).
      They have *not* been checked against the printed paper. 32×32 result:
      max |u − Ghia| 0.80%, |v − Ghia| 0.33% of lid speed (64×64: 0.52%, 0.77%).
      A first-order-looking error turned out to be the test sampler placing
      wall values half a cell beyond the wall.
- [X] Residual convergence monitoring (L2 per equation; =iterate= returns it).
- [X] =rans_converges_residual='s =TBD=: 15,000 iterations to a 5-order drop

      equation's peak, since w and p start at exactly 0. Folded into the

** DONE 2.3 RNG k-ε with atmospheric wall functions [11/11]
Parity record (what OpenFOAM-11 WindNinja actually uses):

three runs (µs; saxpy, 3 float arrays):
| elements   | queued dispatch | dispatch + wait | upload | readback | staging buffer |
|------------+-----------------+-----------------+--------+----------+----------------|
| 25k        |              25 |             500 |    2.4 |      290 |              5 |
| 100k       |              23 |             230 |     35 |      260 |              5 |
| 1M         |              42 |             220 |    460 |      620 |              5 |
| 10M        |             430 |             690 |   4500 |     4800 |              6 |
CPU RANS solver, 100k cells (100×50×20, turbulent): 80 ms per iteration on
1 thread, 9.3 ms on 12 threads.

Findings:
- A queued dispatch costs about 23 µs: a new bind group and a separate
  submit each time. At 10M elements the kernel itself dominates (430 µs,
  about 280 GB/s).
- Against the rule above: about 12 dispatches per iteration would cost
  about 0.3 ms, or 3% of the CPU's 9.3 ms. That's under 10%, so *no kernel
  fusion is planned for Phase 4*. But a GPU iteration at 100k cells should
  itself be well under 1 ms, so the overhead will dominate it. Phase 4 should
  record each iteration's dispatches into one command encoder and one
  submit, and cache bind groups. That's cheaper than fusion; fuse only where
  the profile still says so.
- A wait round trip costs 0.2–0.5 ms. Never wait every iteration: check
  residuals every N iterations, reading back a few reduced values, not the
  fields.
- Readback has a floor of about 0.25 ms (the wait) plus about 8 GB/s. Upload
  is about 9 GB/s at 1M+ (the small-size upload time excludes the GPU-side
  copy).
- Creating a staging buffer costs about 5 µs, which is negligible next to the
  readback. =Buffer::download()= keeps one per call.
- Caveat: this is unified memory. A discrete GPU over PCIe will have different
  transfer costs; re-run =gpu_overhead_bench= on Linux/Windows hardware at
  GATE 4.
*** Tests
- Record the numbers here. If per-dispatch overhead at 100k cells is more
  than 10% of the estimated per-iteration CPU time, plan kernel fusion in

** NEXT 4.2 Kernels, one per solver stage
Design: the CPU solver scatters each face's contribution to both cells
(three race-free OpenMP passes). On the GPU that scatter would race, so each
stage is a *face pass* (one thread per face, writing per-face values to a
face buffer per direction) followed by a *cell gather* (one thread per cell,
summing its six faces with signs). No atomics; results are deterministic.
- [X] Gradients (=gpu::RansSolver::computeGradients=,
      =src/ninja/gpu/gpu_rans{.h,.cpp,_kernels.h}=). Green-Gauss as the CPU's
      (inverse-distance face values; boundary states with the outlets'
      extrapolated velocity). A cell's lower face always contributes −value·S
      and its upper face +value·S, boundaries included, so the gather has no
      special cases, and the face pass writes value·S, keeping the gather at 6
      bindings. Test =gpu/kernel_gradients_matches_cpu=: a 40×12×10 ridge
      grid at 1,000–2,600 m, wind from 280° (inlets W and N), smooth
      non-trivial state. Max relative difference 9.6e-7 (tolerance 1e-5).
      Mutation check: κ 0.41 → 0.40 in the log-profile inlet fails at 0.073.
      The CPU solver gained public =computeGradients()=, =gradient()= and
      =boundary()= for these tests.
